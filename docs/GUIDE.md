# HashNet Studio — полное руководство

Чистая папка программы: оболочка (браузерный интерфейс) + Rust-проект `hashnet_proto` (байтовый трансформер BitNet b1.58 на CUDA) + инструменты подготовки данных.
Всё, что делают кнопки, можно выполнить и командами из терминала — они приведены ниже. В интерфейсе под каждой кнопкой запуска показан «эквивалент в терминале».

```
HashNet_Studio/
├─ start.sh / app.py     оболочка (только стандартный Python 3, ничего ставить не нужно)
├─ ui/index.html         интерфейс
├─ rust/                 проект hashnet_proto (Cargo.toml, src/)
├─ tools/                split_corpus.py, sample_corpus.py, mix_files.py, starcoder_to_txt.py, fetch_repos.py
└─ workspace/            data/ (данные), checkpoints/ (модели), logs/ (журналы всех запусков)
```

## 0. Один раз: подготовка системы (Pop!_OS)

```bash
# драйвер NVIDIA и CUDA toolkit (нужен nvcc/NVRTC), проверка:
nvidia-smi
nvcc --version            # если нет:  sudo apt install nvidia-cuda-toolkit
# Rust:
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source ~/.cargo/env
python3 --version         # нужен Python 3.8+
```
Для конвертации StarCoderData (parquet) дополнительно: `pip install pyarrow`.

## 1. Запуск оболочки

```bash
cd HashNet_Studio
./start.sh                # или: python3 app.py
```
В терминале появится адрес вида `http://127.0.0.1:8765/?t=КЛЮЧ` — браузер откроется сам (если нет — скопируйте адрес).
Оболочка слушает только ваш компьютер (127.0.0.1) и принимает только запросы с ключом из адреса; после перезапуска ключ новый.
Закрытие терминала / Ctrl+C останавливает оболочку и корректно прерывает идущие задачи (чекпойнт сохранится).

Вкладка **Настройки**: папка проекта Rust (по умолчанию `rust/` рядом), рабочая папка, команды `cargo`/`python`.
Если у вас уже есть свой проект (например `/media/tola/Новый том/bit_rust`), укажите его в «Папка проекта Rust» — оболочка будет использовать его.
Первая задача «Обучение»/«Чат»/«Слияние» сама соберёт программу (`cargo build --release`), это занимает 1–3 минуты. Кнопка «Собрать программу» на Панели делает то же вручную.

## 2. Подготовка данных (вкладка «Данные»)

| Что нужно | Кнопка | Команда |
|---|---|---|
| Разобрать большой смешанный файл на классы (rust, проза, чат, диалоги…) | **1. Нарезка** | `python3 tools/split_corpus.py ФАЙЛ --out ПАПКА [--dry-run] [--limit-gb N] [--keep-generated]` |
| Взять из огромного файла ровно N ГБ, равномерно по всему файлу | **2. Выборка** | `python3 tools/sample_corpus.py ИСХОДНЫЙ НОВЫЙ --gb 2 --chunk-mb 1` |
| Соединить несколько файлов в один готовый | **3. Соединение** | `python3 tools/mix_files.py --out mix.txt [--target-gb 2] a.txt@7 b.txt@2 c.txt@1` |
| Сконвертировать StarCoderData (parquet) в текст | **4. StarCoder** | `python3 tools/starcoder_to_txt.py ПАПКА_PARQUET --out code_txt --only rust,python --max-gb-per-lang 3` |

Рекомендуемый порядок:
1. **Нарезка с «Только отчёт»** (dry-run) — посмотрите размеры классов и по 5 образцов каждого; если классы определены плохо — не продолжайте.
2. Нарезка без dry-run. Сгенерированный код и мусор не записываются. Получатся файлы `rust.txt`, `prose_ru.txt`, `chat_ru.txt` и т. д.
3. **Выборка** — если файл слишком велик для обучения (для модели ~35M хватает 2 ГБ).
4. **Соединение** — соберите итоговый файл. Вес без «итогового размера» = сколько раз взять файл (0.5 — половина, 2 — дважды); с итоговым размером веса задают пропорции (7:2:1 → 70/20/10 %).

**Несколько маленьких моделей:** запустите «Соединение» несколько раз с разными наборами файлов и разными именами итоговых файлов (например `mix_rust.txt`, `mix_ru.txt`), затем обучите по модели на каждом. Позже модели можно слить (раздел 5) — но слияние осмысленно только для моделей одной архитектуры с общим «предком» (см. ниже).

## 3. Обучение (вкладка «Обучение»)

### Новая модель
1. «Новая модель» → выберите пресет размера (видно оценку числа параметров и нужного объёма данных ≈ 20 байт на параметр).
2. «Папка модели» — куда писать чекпойнты (по умолчанию `workspace/checkpoints/model1`).
3. «+ Добавить файл» — один или несколько файлов с данными (вес — доля в выборке).
4. Параметры: шагов, batch, accum, lr. **Токенов за шаг = batch × seq × accum.** Если не хватает видеопамяти (8 ГБ) — уменьшите batch, увеличьте accum.
5. **▶ Старт**.

Подсказка по размерам (RTX 4060, 8 ГБ): 38M (d512 L12 seq256) batch 8–16; 86M (d768 L12 seq1024) batch 2, accum 8.

Терминал:
```bash
cd rust && cargo build --release
./target/release/hashnet_proto train --ckpt-dir ../workspace/checkpoints/model1 \
   --d-model 512 --layers 12 --heads 8 --seq 256 \
   --data ../workspace/data/mix.txt --steps 20000 --batch 8 --accum 1 --lr 3e-3 --warmup 200 \
   --ckpt-every 500 --eval-every 500
```

### Остановка и продолжение (ничего не теряется)
* **■ Стоп** (или Ctrl+C в терминале) — программа дописывает чекпойнт и выходит. Остановить можно в любой момент; максимум теряются шаги после последнего чекпойнта, если выключили питание.
* **Продолжить / дообучить** → выберите модель (прерванные помечены «прервана») → **▶ Продолжить**. Обучение идёт с того же шага, с теми же данными и состоянием оптимизатора, а не сначала.

Терминал:
```bash
./target/release/hashnet_proto train --resume --ckpt-dir ../workspace/checkpoints/model1 --steps 20000
```
* **Дообучение на новых данных** (после завершения фазы): отметьте «Начать новую фазу», добавьте файлы, при желании `replay-frac` (доля повтора старых данных, например 0.2, чтобы не забывать прежнее):
```bash
./target/release/hashnet_proto train --resume --new-phase --ckpt-dir ../workspace/checkpoints/model1 \
   --data новые.txt --steps 5000 --replay-frac 0.2
```
Во время обучения видны: шаг, бит/байт (чем меньше, тем лучше; ~8 — случайный шум, 1.0–1.5 — хороший код), val, скорость, остаток времени, график. Полный лог — вкладка «Логи» и папка `workspace/logs/`.

## 4. Чат (вкладка «Чат»)
Выберите модель, введите начало текста или кода — модель **продолжает** его (это не ассистент). Настройки: длина, temperature (ниже — аккуратнее, выше — разнообразнее), top-k, no-repeat N (запрет повторять одинаковые цепочки из N байт; 4–6 убирает зацикливание).
Во время обучения генерация занимает видеопамять и тормозит обучение — оболочка предупреждает.
```bash
./target/release/hashnet_proto gen --ckpt ../workspace/checkpoints/model1 --prompt "fn main() {" \
   --len 300 --temp 0.8 --top-k 40 --no-repeat 4
```

## 5. Слияние (вкладка «Слияние»)
Выберите метод, модели (папки чекпойнтов) и новую пустую папку-результат. Работает на CPU/в ОЗУ, GPU не нужен.

| Метод | Что делает | Требования |
|---|---|---|
| `avg` | среднее весов (alpha — веса) | одна архитектура, общий предок |
| `slerp` | сферическая интерполяция двух моделей (t) | то же, ровно 2 модели |
| `task` / `ties` / `dare` | база + разности (модель − база); ties/dare — прореживание (density/drop) | общая **база**: модель до того, как её дообучали по-разному |
| `stack` | склейка слоёв: из 6+6 слоёв получается 12 (take «0-6,0-6») | размер растёт; после склейки нужно дообучить |

Важно: две модели, обученные с нуля независимо, **усреднять нельзя** — у них разные «внутренние координаты», получится мусор. Работают: ветки одной модели, дообученные на разных данных (база = исходная модель), и `stack`. Сумма параметров «35M + 35M = 70M» достигается только через `stack` (глубже), а не через среднее.
```bash
./target/release/hashnet_proto merge --method avg --model ckA --model ckB --alpha 0.5,0.5 --out ckMerged
./target/release/hashnet_proto merge --method ties --base ckBase --model ckA --model ckB --density 0.2 --lambda 1.0 --out ckMerged
./target/release/hashnet_proto merge --method stack --model ckA --model ckB --take 0-6,0-6 --globals first --out ckStacked
```
Результат — обычный чекпойнт: его можно открыть в «Чате» и дообучать («Продолжить», новая фаза), что особенно нужно после `stack`.

## 6. Сквозной пример «с нуля до финала» (терминал)
```bash
./start.sh                                   # либо всё ниже вручную
python3 tools/split_corpus.py ~/data/big.txt --out workspace/data/split --dry-run
python3 tools/split_corpus.py ~/data/big.txt --out workspace/data/split
python3 tools/sample_corpus.py workspace/data/split/rust.txt workspace/data/rust_2gb.txt --gb 2
cd rust && cargo build --release
./target/release/hashnet_proto train --ckpt-dir ../workspace/checkpoints/m35 --d-model 512 --layers 12 --heads 8 --seq 256 \
    --data ../workspace/data/rust_2gb.txt --steps 20000 --batch 8
# Ctrl+C когда нужно, затем:
./target/release/hashnet_proto train --resume --ckpt-dir ../workspace/checkpoints/m35 --steps 20000
./target/release/hashnet_proto gen --ckpt ../workspace/checkpoints/m35 --prompt "fn main() {" --len 300 --no-repeat 4
```
Проверка качества на отложенных данных: `info` показывает сведения, а val печатается в ходе обучения (`--eval-every`).
`./target/release/hashnet_proto info --ckpt ../workspace/checkpoints/m35`

## 7. Если что-то не так
* **«нет проекта / Cargo.toml»** — укажите папку проекта в «Настройки».
* **Ошибка сборки cudarc / nvcc** — проверьте `nvcc --version` и `nvidia-smi`; драйвер и toolkit одной ветки.
* **CUDA out of memory** — уменьшите batch (и увеличьте accum), или seq / размер модели. Закройте другие программы на GPU.
* **«уже идёт обучение»** — одновременно можно только одно обучение; сначала «Стоп».
* **Слияние выдало мусор** — модели не имели общего предка (раздел 5).
* **Модель зацикливается** — включите no-repeat N (4–6), поднимите temperature.
* **Нет pyarrow** — `pip install pyarrow` (только для StarCoder).
* Журналы всех запусков: `workspace/logs/`. Остановить зависшую задачу: «Логи» → выбрать → «Остановить» (повторно — SIGKILL не предусмотрен кнопкой; в крайнем случае `pkill hashnet_proto`).

## 8. Заметки
* Оболочка не меняет формат чекпойнтов и модель — это обёртка над теми же командами.
* Папка `rust/` — копия проекта на момент сборки пакета; при желании используйте свой проект (Настройки).
